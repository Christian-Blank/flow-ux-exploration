# Screen Spec Template

Use this template when adding a new screen or formalizing a placeholder route.

---

# <Screen Name>

## Purpose

- What user problem this screen solves.
- What success looks like when the user leaves the screen.

## Route / Surface

- Route: `<path>`
- Visible in nav? (where)
- Requires onboarding completion? (yes/no)

## Entry Points

- From which screens/CTAs the user can arrive here.
- Deep links (if any).

## Layout

Describe the top-level page structure (header, columns, panels, footers).

## Primary Actions

For each primary action:
- Trigger (button/link)
- Preconditions (what must be true)
- System response (UI + data changes)
- Next state / navigation

## Secondary Actions

- Optional controls and explorations.

## States

- Empty states
- Loading states (if relevant)
- Error states
- Disabled states (what conditions disable CTAs)

## Data & Rules (Product-Level)

- What data is displayed and how it is derived.
- Any business logic, scoring, ranking, filtering.

## Content / Copy

- Key headings
- Button labels
- Microcopy notes (tone and conventions)

## Analytics (Optional)

- Events to track
- Success metrics

## Accessibility Notes (Optional)

- Keyboard/focus
- Contrast
- Motion preferences

## Open Questions

- Decisions still needed.
